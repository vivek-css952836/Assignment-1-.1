Assignment 1.1 — How a Website Works
Explanatory Paragraph
When you type a URL into your web browser (the client), it first translates the web address into an IP address using the Domain Name System (DNS) and sends an HTTP/HTTPS (Hypertext Transfer Protocol / Secure) request to a remote server. The server processes this request, occasionally fetching stored data from a database if the site is dynamic (generating personalized content on the fly), unlike a static website which simply returns pre-built files like HTML, CSS, and JavaScript. Finally, the server sends back an HTTP response containing these files, and your browser renders them into the fully loaded webpage you see on your screen.
Key Definitions & Concepts
Browser / Client: The software on your device (like Google Chrome, Safari, or Firefox) that requests, renders, and displays web pages.
Server: A powerful remote computer that stores website files, processes incoming requests from clients, and delivers the appropriate data back.
Database: An organized collection of data used by dynamic websites to store user information, posts, products, and other content that changes frequently.
HTTP vs. HTTPS:
HTTP (Hypertext Transfer Protocol): The foundational protocol used for transmitting data between a browser and a web server in plain text.
HTTPS (Hypertext Transfer Protocol Secure): The secure, encrypted version of HTTP that protects sensitive data (like passwords and credit card details) from interception using SSL/TLS protocols.
Request-Response Cycle: The fundamental communication model of the web where the client (browser) sends a request to the server, and the server processes it and sends back a response.
Static vs. Dynamic Websites:
Static Website: Consists of fixed, pre-rendered files (HTML/CSS) that look the same for every visitor.
Dynamic Website: Uses databases and server-side processing to generate unique, interactive content tailored to the user or real-time actions.
